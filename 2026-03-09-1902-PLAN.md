# 2026-03-09 19:02 Plan — Dynamic Simulation Evaluation, Improvement, and Two-Track Traceability

## Summary
- 현재 엔진의 핵심 방향은 맞다. deterministic controller, trait calibration, generation-level diversity 유도는 유지한다.
- 다음 단계의 목표는 세 가지다.
  - `runtime fidelity`를 더 올린다
  - `dynamic builder`를 manual-script 수준 contract까지 완성한다
  - `guided/exploratory` 두 트랙의 결과를 phase/turn/candidate/action/world-state까지 역추적 가능한 trace system으로 바꾼다
- 기준 문서는 최신 결과가 반영된 `simulation_engine/2026-03-08_233500_실험목표.md`로 두고, `data_scarcity_ml_vs_rule_based_N_hours.md`는 uncertainty, counterfactual, logging, ML defer 원칙만 채택한다.
- 다음 설계의 최우선 산출물은 “더 좋은 수치”가 아니라 “좋은 수치와 나쁜 수치가 왜 나왔는지 설명 가능한 구조화 데이터”다.

## Current Assessment
- 강점:
  - drift, C-trait, contradiction은 이미 강하게 개선됐다
  - novel scripts, scaling, user-input happy path는 동작한다
  - selection stochasticity는 해롭고, diversity ceiling은 selection이 아니라 generation/builder 쪽 문제라는 것이 확인됐다
- 약점:
  - envelope violations는 아직 목표 미달이다
  - policy-spillover 계열에서 convergence가 높다
  - user-input builder는 runnable은 되지만 full action-layer metadata를 만들지 못한다
  - 현재 reporting은 aggregate는 좋지만 lineage가 약하다
- 결론:
  - production baseline은 여전히 rule-based, deterministic, audit-friendly로 유지한다
  - traceability는 보고서 기능이 아니라 core architecture requirement로 올린다

## Keep / Defer / Reject
### Keep now
- deterministic controller
- banded target matching
- per-slot action vocabulary rotation
- sequential sampling with `mean ± CI`
- candidate-pool 기반 counterfactual evaluation
- sampled audit only
- clean/contaminated split

### Defer
- hierarchical Bayes
- lightweight reranker
- judge distillation
- adaptive topology research ideas

### Reject for now
- default softmax selection
- always-on jury evaluation
- RL / preference optimization
- per-script hard-coded tuning as main path

## Workstream 3 — Two-Track Traceability

- 모든 headline metric은 다음 경로로 역추적 가능해야 한다.
- `track outcome -> run -> phase -> turn -> candidate/action/world-state evidence`

## Experiment Sequence
### Phase 1 — Trace foundation
- trace IDs 추가
- normalized trace tables 추가
- 현재 benchmark output을 trace data로 재구성 가능하게 만든다

### Phase 2 — Runtime residual fixes
- E calibration
- family budget penalty
- envelope-aware prompt hint
- 7 default scripts × 4 reps 재실행
- gate:
  - drift <= 0.16
  - E <= 0.16
  - violations < 5.0
  - convergence < 0.55

### Phase 3 — Builder completion
- brief-to-script full contract generation 구현
- 10 briefs, 5 families 이상, 3 reps
- gate:
  - schema-valid >= 95%
  - runnable >= 90%
  - clean >= 80%
  - completeness >= 0.90

### Phase 4 — Dynamic simulation validation
- OOD manual scripts + generated scripts 함께 평가
- builder failure / runtime failure / metric ambiguity를 분리해 attribution 생성
- action execution enabled runs에서만 action/world-state headline 평가

### Phase 5 — Sampled audit
- 일부 run만 human/jury audit
- audit 결과를 attribution layer에 calibration evidence로만 연결

## Test Plan
- lineage integrity
  - selected candidate는 항상 candidate row에 존재
  - executed action은 항상 turn row에 연결
  - aggregate metric은 항상 supporting trace를 가짐
  - builder-generated run은 항상 builder trace를 가짐
- reconstruction
  - aggregate report를 trace tables만으로 재생성 가능
  - run 하나를 turn/action/state sequence로 lossless replay 가능
- visualization readiness
  - `trace_views/`만으로 waterfall, heatmap, timeline, sankey, decision card 생성 가능
- reliability/statistics
  - raw counts + rates 동시 저장
  - `mean ± 95% CI`
  - zero-variance metric auto-flag
  - clean/contaminated split 유지
- builder tests
  - completeness score deterministic
  - missing contract fields가 run outcome에도 반영됨

## Assumptions
- product priority는 explainable dynamic simulation이다.
- traceability는 선택 기능이 아니라 core design requirement다.
- production baseline은 rule-based, deterministic, audit-friendly다.
- later ML은 새 trace tables를 학습 데이터와 attribution source로 사용할 뿐, 현재 control kernel을 대체하지 않는다.
