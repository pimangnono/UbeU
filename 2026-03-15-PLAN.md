# Simulation Engine Enhancement Plan (Revised)

## Objective

Production-level simulation engine with **full traceability** of actor-actor and actor-environment interactions, demonstrating WHY guided/exploratory outcomes reached their conclusions.

## Problems Addressed

1. Script generation fails 33% on 10-actor scripts (JSON parse errors)
2. Relationship tracking is flat (binary keyword matching, no episodic memory)
3. No influence attribution — can trace WHAT happened but not WHAT CAUSED IT
4. No causal chain from initial positions → actions → state changes → outcome
5. Keyword matching misses paraphrases in some scoring criteria
6. No post-hoc self-consistency audit
7. Actors have no real-world entity knowledge

## Revised Implementation Order

| Priority | Technique | Impact | Effort | Serves Traceability? |
|----------|-----------|--------|--------|---------------------|
| 1 | T3: Decomposed Config Generation | High (reliability) | Medium | Prerequisite |

| 3 | **T6: Influence Attribution (NEW)** | **Critical (traceability)** | **Medium** | **Core deliverable** |
| 4 | T7: Hybrid Semantic Scoring (NEW) | Medium (accuracy) | Medium | Improves fidelity |

| 6 | T5: RAG Knowledge Enrichment | Medium (grounding) | High | Nice-to-have |

## T1+T4: NetworkX Graph + Episodic Memory (REVISED)

### Key change from previous plan: LLM extraction feeds memory only, NOT scoring

The candidate selection loop remains **fully deterministic** (keyword-based scoring). LLM extraction enriches the episodic memory layer, which is injected into generation prompts (influencing what candidates the LLM produces, not how they're scored).

### Architecture: 3 separated concerns (not 1 overloaded class)

## T6: Influence Attribution (NEW — core traceability deliverable)

### Goal

Answer the question: **"Why did the simulation reach this outcome?"** by recording causal influence chains between actors, actions, and state changes.

### The Problem

Current trace events are flat JSONL files. You can see:
- Action X happened (action_events.jsonl)
- State Y changed (world_state_deltas.jsonl)
- Relationship Z shifted (relationship_events.jsonl)

But you CANNOT see: "Action X by Actor A → caused state change Y → influenced Actor B's position in turn Z → led to outcome." There's no causal linking.

### Data Model

```python
# Added to simulation_engine/relational_memory.py

@dataclass
class InfluenceEvent:
    turn_index: int
    influenced_actor_id: str        # who changed
    influencing_source: str         # actor_id or "world_event:{event_id}"
    mechanism: str                  # "argument" | "concession" | "pressure" |
                                    # "world_event" | "trait_conflict" | "relationship_shift"
    trait_involved: str | None      # which OCEAN trait drove the reaction (if applicable)
    scoring_criteria_involved: list[str]  # which scoring dimensions shifted most
    state_keys_affected: list[str]  # world state keys that changed as result
    drift_delta: float              # persona drift change this turn
    magnitude: float                # influence strength (from scoring component deltas)
    evidence_excerpt: str           # first 100 chars of the turn
    causal_chain_id: str            # groups related events into chains

class InfluenceTracker:
    """Records and queries causal influence chains."""

    events: list[InfluenceEvent]
    chains: dict[str, list[InfluenceEvent]]  # causal_chain_id → ordered events

    def record_turn_influence(
        self,
        actor_id: str,
        turn_index: int,
        previous_turn: dict,          # previous speaker's turn data
        scoring_breakdown: dict,       # winning candidate's score components
        previous_scoring: dict | None, # same actor's previous scoring
        world_event_injected: bool,
        drift_before: float,
        drift_after: float,
        state_delta: dict[str, float],
        relationship_changes: list[dict],
    ) -> list[InfluenceEvent]:
        """Deterministic influence detection — no LLM calls.

        Rules:
        1. If drift_delta > 0.03 on any trait after responding to Actor B
           → InfluenceEvent(mechanism="argument", trait_involved=worst_trait)
        2. If world_event was injected this turn and state changed
           → InfluenceEvent(mechanism="world_event")
        3. If relationship trust/tension changed > 0.08 between two actors
           → InfluenceEvent(mechanism="relationship_shift")
        4. If scoring criterion X shifted > 0.02 between this turn and actor's previous turn
           → record scoring_criteria_involved
        5. If sycophancy_risk increased > 0.15 after another actor's strong statement
           → InfluenceEvent(mechanism="pressure")
        """

    def build_causal_chains(self) -> dict[str, list[InfluenceEvent]]:
        """Link influence events into chains.

        Chain rule: Event A links to Event B if:
        - B.influenced_actor == A.influencing_source (the influenced becomes the influencer)
        - B.turn_index > A.turn_index
        - B.state_keys_affected overlaps A.state_keys_affected (same domain of influence)
        """

    def trace_outcome_path(
        self,
        final_world_state: dict[str, float],
        initial_world_state: dict[str, float],
    ) -> list[PivotalMoment]:
        """Walk backwards from final state to find pivotal moments.

        1. Find state keys with largest |final - initial| delta
        2. For each, find influence events that moved them most
        3. Chain events together: "A influenced B which influenced C..."
        4. Return ordered list of pivotal moments with full attribution
        """

    def actor_influence_summary(self) -> dict[str, ActorInfluenceSummary]:
        """Per-actor: influenced_by (who changed them), influenced (who they changed),
        net influence score, dominant mechanism."""

    def serialize(self) -> list[dict]
    def deserialize(data) -> None
```

    turn_index: int

                                    #  uncertainty from 0.5 → 0.72"

All influence detection uses data already computed by the controller:
- `drift_delta` — from `estimate_actor_traits_from_turns()` (deterministic)

- `state_delta` — from world state updates (deterministic)
- `relationship_changes` — from `update_relationships_from_text()` (keyword-based, deterministic)

No new LLM calls. Just arithmetic on existing scoring data.

## T7: Hybrid Semantic Scoring (NEW)

### Goal

Add embedding-based features as **supplementary signals** (low weight) in the selection loop, while keeping keyword matching as primary. NOT a replacement — an augmentation.

### Why Not Full Replacement

| Concern | Detail |
|---------|--------|
| **Style differentiation** | The 4 candidates say the same thing differently. Embeddings compress semantic content → similar scores for all 4 → controller can't differentiate. Keywords detect surface-level choices ("I disagree" vs "That's interesting, but...") which is exactly what style differentiation needs. |
| **Calibration** | All 30 scoring weights are tuned to keyword-frequency distributions. Full replacement invalidates calibration. |
| **Sycophancy precision** | "Insightful observation" (sycophancy) vs "Your data convincingly shows X" (genuine update) look similar in embedding space. Keywords catch specific low-effort agreement patterns without false positives. |
| **Action classification** | "I'll take ownership" (assign_owner action) vs "I'm concerned about ownership" (not an action). Needs discrete classification, not similarity. |
| **Speed** | Embeddings: ~5ms each. 640 per run. Acceptable but non-trivial. |

### Where Semantic DOES Help (supplementary)

| Scoring Criterion | Current | Add Semantic? | Why |
|-------------------|---------|--------------|-----|
| Identity consistency (w=0.16) | 4+ char token overlap with role/incentives | **Yes** (w=0.04 of the 0.16) | "workers aren't compensated fairly" paraphrases "wage theft" — embedding catches, keyword misses |
| Trait target alignment (w=0.14) | POLAR_SIGNAL_LIBRARY (40 phrases) | **Yes** (w=0.04 of the 0.14) | "Have we considered a radically different approach?" = high-O, but no keyword match |
| Situational adequacy (w=0.09) | Token overlap with phase cues | **Yes** (w=0.03 of the 0.09) | Embedding similarity between response and phase goal is more robust than token intersection |
| Sycophancy (w=-0.08) | 8 acknowledgment patterns | **No** | Precision > recall here. False positives on genuine agreement are worse than missed sycophancy. |
| Genericity (w=-0.07) | 5 boilerplate phrases | **No** | Exact filler detection. Semantic would over-trigger on substantive hedging. |
| Action type detection | ACTION_CUE_PATTERNS | **No** | Classification, not similarity. Keywords map specific verbs → specific types. |
| Strength/confidence | 5+4 keywords | **No** | Binary signal. Keywords are exact. |
| Interaction progress (w=0.04) | Action keywords | **No** | Too low weight to justify complexity. |
| Policy match (w=0.02) | Stance keywords | **No** | Too low weight. |

### Implementation

```python
# simulation_engine/semantic_scorer.py

from sentence_transformers import SentenceTransformer

class SemanticScorer:
    """Local embedding-based supplementary scoring. Deterministic."""

    def __init__(self, model_name="all-MiniLM-L6-v2"):
        self.model = SentenceTransformer(model_name)
        self._prototype_cache: dict[str, np.ndarray] = {}

    def init_for_actor(self, actor_spec):
        """Pre-compute prototype embeddings at simulation init (once per actor)."""
        # Identity prototypes: embed role description + incentives + concerns
        self._prototype_cache["identity"] = self.model.encode(
            f"{actor_spec.role}. {'. '.join(actor_spec.incentives)}. {'. '.join(actor_spec.concerns)}"
        )
        # Trait pole prototypes: embed canonical high/low expressions per trait
        for trait in ("O", "C"):
            pole, _ = trait_pole(actor_spec.personality_prior[trait])
            if pole != "neutral":
                prototype_text = TRAIT_PROTOTYPE_SENTENCES[trait][pole]
                self._prototype_cache[f"{trait}_{pole}"] = self.model.encode(prototype_text)

    def identity_similarity(self, response_text: str) -> float:
        """Cosine similarity between response and actor identity prototype."""
        response_emb = self.model.encode(response_text)
        return float(cosine_similarity(response_emb, self._prototype_cache["identity"]))

    def trait_alignment_similarity(self, response_text: str, trait: str, pole: str) -> float:
        """Cosine similarity between response and trait pole prototype."""
        key = f"{trait}_{pole}"
        if key not in self._prototype_cache:
            return 0.5  # neutral
        response_emb = self.model.encode(response_text)
        return float(cosine_similarity(response_emb, self._prototype_cache[key]))

# Canonical prototype sentences for trait poles
TRAIT_PROTOTYPE_SENTENCES = {
    "O": {
        "high": "What if we tried a completely different approach? Let me reframe this problem. "
                "There's an interesting tradeoff we haven't explored. Consider this alternative hypothesis.",
        "low": "Let's stick with what's proven. The data supports the standard approach. "
               "We should verify with evidence before changing anything. Start small and validate.",
    },
    "C": {
        "high": "I'll take ownership of this. First we do X, then Y. Let me set a deadline. "
                "Who is responsible for each step? We need a structured plan.",
        "low": "Let's stay flexible and adapt as we go. We can iterate on this. "
               "No need to lock everything down yet. Take a lightweight approach first.",
    },
}
```

### Performance
- Model load: ~2s (once at init)
- Per-embedding: ~5ms (local CPU)
- Per-turn: 4 candidates x 2 similarities = 8 embeddings x 5ms = ~40ms
- Per-run (40 turns): ~1.6s additional
- Deterministic: same model + same text = same embedding = same score

### Where Semantic Matching Should NOT Be Used (and why keywords stay)

**Sycophancy detection**: "That's a really insightful observation" and "Your data convincingly shows X, so I've revised my view" are semantically similar but categorically different (sycophancy vs genuine position update). The 8 keyword patterns catch specific low-effort agreement phrases with precision. Semantic matching would produce false positives on legitimate agreement and penalize actors who genuinely update their positions — exactly the opposite of what we want.

**Genericity detection**: "We should think carefully about all options" is generic. "We should carefully evaluate Option A against Option B given the budget constraint" is substantive. Keywords detect exact boilerplate. Semantic matching would conflate these.

**Action type classification**: This needs discrete mapping (text -> 1 of 8 action types), not similarity. "I'll take ownership of this timeline" = assign_owner. "I'm concerned about ownership of intellectual property" = NOT an action. The keyword "own"/"assign" maps to the action; embedding similarity between these sentences would be misleadingly high.

**Relationship sentiment** (state_ledger.py post-hoc): This IS replaced — but by T4's structured LLM extraction (1 call/turn), not by embeddings. LLM extraction can parse "I hear your concerns, but my position hasn't changed" as a challenging sentiment with specific topic/reason. Embeddings alone can't extract structured relationship data.

## Traceability Data Flow (the core deliverable)

```
Per Turn:
  Actor generates response
    -> Controller scores 4 candidates (keyword + semantic)      [T7]
    -> Winner selected, scoring breakdown recorded
    -> LLM extracts relationship changes -> EpisodicMemory       [T4]
    -> State delta computed, world state updated
    -> InfluenceTracker.record_turn_influence()                  [T6]
      |-- Compares scoring breakdown vs previous turn
      |-- Detects drift_delta, state_delta, relationship shifts
      \-- Records InfluenceEvent with mechanism + trait + evidence

At Simulation End:
  InfluenceTracker.build_causal_chains()                        [T6]
    -> Links events: "A influenced B who influenced C"
  InfluenceTracker.trace_outcome_path()                         [T6]
    -> Walks backward from final state to find pivotal moments
  SimulationGraph.actor_pagerank()                              [T1+T4]
    -> Who was most structurally influential?
  Post-interview (optional)                                     [T2]
    -> Self-consistency audit

Output:
  trace_views/influence_events.jsonl     — per-turn influence records
  trace_views/causal_chains.jsonl        — linked causal chains
  trace_views/pivotal_moments.json       — ranked turning points with attribution
  trace_views/actor_influence_summary.json — per-actor influence profile
  benchmark_report.md -> "## Outcome Attribution" section
```

This gives a reader the ability to ask: "Why did the California AB5 simulation end in stalemate?" and get:
> "Pivotal moment #1 (turn 8): Actor C (disability advocate, high-O=0.75) proposed preserving flexibility, causing trust drop between Union Organizer and Gig Worker (trust 0.62->0.48). This triggered Actor B (union organizer) to escalate with request_evidence in turn 10, shifting uncertainty from 0.5->0.72. The cascade continued through turns 12-15 as no actor resolved the evidence request, leading to deferred decisions and final stalemate."
