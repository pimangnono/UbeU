- **Improvement path**:
  1. Restore partial persona weight: `identity_consistency` 0.15→0.16, `persona_drift` 0.15→0.17 (reclaim 0.03)
  2. Lower windowed drift threshold from 0.15 → 0.10 to catch gradual C/E drift

## 6. Cross-Cutting Findings

### 6.1 Negotiation uniqueness ceiling at 0.667
- All 12 runs produce exactly 0.667 — zero variance
- This suggests the deterministic tactic seeding (Phase 2.5) creates consistent differentiation but locks in at a fixed level
- With 3 actors and the hash-based 4-profile rotation, the same 3 profiles are always selected for a given script
- **Action**: Add a `run_index` component to the tactic seed hash: `hash(actor_id + phase_name + str(run_index))` to vary across repetitions

### 6.2 Conscientiousness trait is hardest to maintain
- C drift is the largest across both tracks (0.227 guided, 0.273 exploratory)
- Likely because the simulation format itself (structured discussion, action proposals) rewards C-typical behaviors (planning, structure markers) regardless of the target prior
- LLMs default to structured, organized output → inflates C estimates
- **Action**: Adjust C estimation formula in `metrics.py` or add C-specific calibration offset

### 6.3 Guided vs Exploratory gap is narrowing
- Baseline gap was significant; now both tracks show similar patterns
- Exploratory benefited more from Phase 1.5 (action vocab) and Phase 3.1 (implicit goals)
- Guided benefited more from Phase 1.1 (slot rotation) and Phase 1.4 (weight rebalance)

### 6.4 Private world events appear to work but impact is unclear
- The 4 private events injected (Phase 3.2) didn't measurably change metrics
- Need to inspect individual run transcripts to verify actors actually reference private information
- **Action**: Add a `private_event_utilization` metric to track whether actors incorporate private information

## 7. Metric Reliability Audit (2026-03-08 23:50 KST)

### 7.1 negotiation_uniqueness_rate — DEGENERATE METRIC (small-N artifact)

**Problem**: NEGOTIATION phase has `max_turns: 3` in every script. With 3 actors in round-robin, exactly 3 action proposals are produced. The metric `unique_families / 3` can only take values {0.333, 0.667, 1.0}. It is a 3-value discrete distribution, not a continuous measure.

**Evidence**:
- All 6 full guided runs: exactly 0.6667 (zero variance)
- All 6 full exploratory runs: exactly 0.6667 (zero variance)
- All 6 baseline engine runs: exactly 0.3333 (zero variance)
- The "improvement" from 0.333→0.667 means exactly ONE actor changed family — not a systematic quality gain
- Paradoxically, naive baseline scores 0.833 (higher than engine) because free-text produces more varied families by chance

**Conclusion**: Cannot be used as evidence of quality improvement. The 0.333→0.667 jump is structurally inevitable given the tactic seeding change, but it doesn't prove genuine negotiation diversity.

### 7.2 structured_action_validity_rate — PROMPT TEMPLATE ARTIFACT

**Problem**: Denominator (`action_bearing` proposals) is only 2-5 per run. The improvement from 0.333→0.833 is driven by Phase 1.5 injecting explicit action vocabulary into prompts, which makes the model output structured `action_type` + `target_key` fields that the validator trivially accepts.

**Evidence**:
- In 3 of 6 experiment batches, this metric has exactly zero variance
- The metric measures "did the structured prompt template successfully elicit JSON" rather than "did actors produce higher-quality actions"
- The naive baseline has higher variance (0.0-1.0 range) because free-text pattern matching is inherently noisier

**Conclusion**: The prompt change works mechanically but the metric conflates format compliance with behavioral quality. Valid proposals ≠ better negotiation outcomes.

### 7.3 action_family() mapping granularity

8 action types collapse to 6 families. With 3 actors choosing from 6 families uniformly at random, expected uniqueness is ~0.72. The engine's 0.667 is BELOW random chance, suggesting the engine may be actively coordinating actors toward similar families despite the diversity interventions.

### 7.4 Metric Reliability Classification

| Metric | Reliability | Notes |
|---|---|---|
| persona_drift_mae | **HIGH** | Continuous, per-trait, meaningful variance |
| commitment_contradiction | **MEDIUM** | Binary per-turn, but large enough sample |
| envelope_violations | **MEDIUM** | Integer count, reasonable range |
| action_family_convergence | **LOW** | Same small-N issue as negotiation_uniqueness but across all phases |
| role_action_diversity | **LOW** | Derived from convergence, same granularity limit |
| negotiation_uniqueness | **DEGENERATE** | 3-value discrete, zero intra-batch variance |
| structured_action_validity | **LOW** | Tiny denominator, prompt-driven |
| relationship_inconsistency | **MEDIUM** | Continuous but often flat (0.0) |
| state_trajectory_variance | **LOW** | Near-zero in dialogue-only mode |

### 7.5 Recommended Metric Improvements

1. **Compute diversity metrics across ALL phases** (not just NEGOTIATION) to increase denominator from 3 to 11
2. **Report raw counts alongside rates**: "2/3 unique families" is more honest than "0.667 uniqueness rate"
3. **Add semantic action diversity**: Instead of family-level grouping, measure lexical diversity of action descriptions
4. **Add inter-run variance as a meta-metric**: If a metric has zero variance across repetitions, it lacks discriminative power
5. **Replace action_validity with action-outcome quality**: Measure whether proposed actions change world state in coherent ways (requires action engine)

## 9. Experiment Sequence Toward Dynamic Simulation (2026-03-09 00:05 KST)

### Design Principle

The ultimate goal is **dynamic simulation from user input** — users define their own scenarios, stakeholders, and personality priors. This means:
- No script-specific tuning (hard-coded duplication penalties, hand-written implicit goals)
- No fixed actor count (must work for 2-6+ actors)
- No fixed phase structure (users may want 2-5 phases)
- Metrics must have statistical power at variable N
- The engine must produce good simulations for inputs it has never seen

The current 4 benchmark scripts are **validation fixtures**, not the product. Repeating them further risks overfitting. Each experiment below tests a different generalization axis.

---

### Experiment 1: Fix Regressions + Fix Metrics (code only, no new runs)

**Goal**: Unblock reliable measurement before running more experiments.

**Changes**:
1. Fix persona drift regression:
   - Restore scoring weights: `identity_consistency` 0.15→0.16, `persona_drift` 0.15→0.17
   - Lower windowed drift threshold: 0.15→0.10
   - Add C-trait calibration offset in `estimate_actor_traits_from_turns`
2. Fix degenerate metrics:
   - Compute `negotiation_uniqueness` and `action_family_convergence` across ALL phases (denominator 3→11)
   - Report raw counts alongside rates in benchmark output
   - Add inter-run variance as a meta-metric to flag zero-variance metrics automatically

**Why first**: Can't evaluate anything if metrics are broken and drift is regressing. No point running experiments with unreliable measurements.

**Validation**: Rerun the same 4 scripts × 3 reps to confirm (a) drift ≤ baseline, (b) diversity gains preserved, (c) metrics show non-zero variance.

---

### Experiment 2: Generalization Test — Novel Scripts (same engine, new scenarios)

**Goal**: Test whether improvements hold on scenarios the engine has never seen.

**Setup**:
- Create 2 NEW scripts from scratch — different domains, different stakeholder dynamics:
  - **Script A**: "University department merger" — 4 actors (dean, 2 department heads, student rep). Tests: 4-actor scaling, academic domain, power asymmetry
  - **Script B**: "Startup equity split" — 3 actors (technical founder, business founder, early employee). Tests: high-conflict negotiation, personal stakes, trust-heavy dynamics
- Use ONLY generic engine parameters (no per-script duplication penalties or sparsity overrides)
- Run both guided and exploratory modes

**What we learn**:
- Do per-script overrides in manual_scripts.py actually matter, or does the engine generalize?
- Do implicit_goals need to be hand-crafted, or can the engine generate natural tension from role + incentive + concern alone?
- Does 4-actor scaling change convergence dynamics?

**Pass criteria**: Within 15% of 4-script benchmark on persona_drift and commitment_contradiction. Diversity metrics should show non-degenerate variance.

---

### Experiment 3: User-Input Simulation — Zero Hard-Coding

**Goal**: Simulate the actual product experience. A user provides a brief, and the engine generates everything.

**Setup**:
- Build a minimal `generate_script_from_brief(brief: str) -> SimulationScript` function that:
  - Takes a 2-3 sentence user brief (e.g., "My team is debating whether to migrate from AWS to GCP. The CTO wants it, the DevOps lead is worried, and the CFO wants cost data.")
  - Uses an LLM call to generate: stakeholders (names, roles, personality priors, incentives, concerns), phases (with appropriate goals/cues), and world events
  - Applies NO manual overrides — uses only default engine parameters
- Run 3 different user briefs × 3 reps each

**What we learn**:
- Does the engine work at all with LLM-generated scripts?
- Are default parameters sufficient, or do they need per-scenario calibration?
- What breaks first: persona fidelity, action diversity, or structural coherence?

**Pass criteria**: Clean runs (no crashes), persona_drift < 0.20, commitment_contradiction < 0.05. These are relaxed targets for the generalization stress test.

---

### Experiment 4: Variable Actor Count + Phase Structure

**Goal**: Prove the engine scales beyond the 3-actor × 4-phase fixture.

**Setup**:
- Take Script A from Experiment 2 (4 actors) and create variants:
  - 2-actor version (just the 2 department heads)
  - 5-actor version (add CFO and faculty union rep)
  - 3-phase version (drop CLOSING, merge into NEGOTIATION)
  - 5-phase version (add EXPLORATION between TENSION and NEGOTIATION)
- Run each variant × 2 reps

**What we learn**:
- Does convergence worsen with more actors? (expected: yes — more actors, more family collisions)
- Does drift worsen with fewer actors? (expected: yes — less context to anchor persona)
- Do phase count changes break the tactic seeding or family cap logic?

**Pass criteria**: No crashes, metrics scale monotonically (more actors → slightly worse convergence but similar drift)

---

### Experiment 5: Softmax + Stochastic Evaluation

**Goal**: Evaluate whether deterministic selection is limiting inter-run variation.

**Setup**:
- Enable `use_softmax_sampling=True` with `tau=0.12`
- Run the original 4 scripts × 5 reps (more reps needed to measure variance)
- Compare inter-run variance of all metrics against deterministic baseline

**What we learn**:
- Does softmax produce meaningfully different simulation outcomes across runs?
- Is tau=0.12 the right temperature, or does it collapse to argmax in practice?
- Does increased stochasticity hurt persona fidelity?

**Pass criteria**: Inter-run variance > 0 for all metrics, persona_drift within 0.02 of deterministic baseline.

---

### Experiment Dependency Chain

```
Exp 1 (fix code)
  ↓ validation run
Exp 2 (novel scripts)     ← tests generalization
  ↓
Exp 3 (user-input)        ← tests product readiness (depends on Exp 2 learnings)
  ↓
Exp 4 (variable actors)   ← tests scaling (can run parallel with Exp 3)
  ↓
Exp 5 (softmax)           ← tests stochasticity (can run parallel with Exp 4)
```

### What NOT to do

- **Don't repeat the 4 benchmark scripts** with the same settings — that's overfitting, not progress
- **Don't add more hard-coded implicit_goals** to existing scripts — that's manual labor that won't scale
- **Don't increase reps beyond 3** on the same scripts — diminishing returns on statistical power with degenerate metrics
- **Don't tune per-script parameters** — the product needs one set of defaults that works everywhere

- Drift: 0.150 (2-actor) → 0.154 (5-actor) — only +0.004 increase. Engine handles 5+ actors without degradation.
- Diversity: 0.917 (2-actor) → 0.820 (5-actor) — slight decrease, expected since more actors means more family collisions.
- Violations: 3.5 → 6.5 — scales roughly linearly with actor count (more actors = more envelope checks). Expected behavior, not a problem.
- C-trait error: 0.145 (2-actor) → 0.280 (5-actor) — C-trait gets harder with more actors. More actors dilute the individual persona signal.

**2. Phase count has stronger impact on drift than actor count**
- 3-phase (0.196) is the worst drift — dropping CLOSING removes the commitment-anchoring phase that reinforces persona consistency.
- 5-phase (0.172) is better than 3-phase — the extra EXPLORATION phase actually helps by giving actors more context to anchor persona.
- The 3-phase variant also has the worst envelope violations (8.5) — without CLOSING, the simulation ends abruptly and persona boundaries get tested more aggressively in NEGOTIATION.

**3. 3-phase achieves perfect diversity (convergence=0, diversity=1.0)**
- By dropping CLOSING, 100% of remaining turns are substantive discussion → no "wrapping up" convergence.
- This is a degenerate result: the metric is perfect because there are fewer turns, not because of better quality.
- However, it does suggest that CLOSING phase is a convergence magnet — all actors default to similar "summarize and agree" patterns.

**4. All action-layer metrics are 0.0 across all variants**
- structured_action_validity, owner_resolution, state_transition_coherence, action_plan_alignment — all zero.
- Root cause: the scaling variants use generic `SimulationScript` construction without the action-layer metadata (phase_action_policies, actor_action_preferences) that the benchmark scripts have.
- This is NOT a bug — the scaling variants intentionally test "default parameters only". But it means action-layer features aren't being tested in scaling scenarios.

**5. Zero commitment contradictions across all 8 runs**
- Consistent across 2, 3, 5-actor and 3, 4, 5-phase variants.
- The engine's commitment tracking is robust to structural variation.

### Scaling conclusions:
- **Actor scaling**: Engine is robust from 2 to 5+ actors. Drift increase is minimal (<0.005). Diversity naturally improves with fewer actors (less collision) but remains good at 5.
- **Phase scaling**: 4-phase (default) is the sweet spot. 3-phase causes drift regression; 5-phase is viable but adds time without proportional benefit.
- **Recommendation**: Default 4-phase structure is correct. For user-input briefs, constrain to 3-5 phases. For 5+ actors, add an extra NEGOTIATION turn to compensate for per-actor speaking time reduction.

### Next move:
- Exp 5 (softmax sampling) proceeds as planned — the deterministic selection is confirmed to work at variable scale, so softmax should be tested on the baseline fixture.
- One adjustment: include a 5-actor variant in Exp 5 to verify softmax works at scale too.

The experiment conclusively shows:
- At tau=0.12, softmax degrades fidelity (-12.7% drift, +1.25 violations) without improving any diversity metric
- The diversity ceiling is structural (action family convergence, role diversity) not selection-based
- Relationship dynamics improve but at too high a cost

### Recommendations:

**1. Do NOT enable softmax by default.** The deterministic selection is strictly better at current tau.

**2. If inter-run variation is needed, fix it at the generation stage, not selection:**
- Add `run_index` to the negotiation tactic seed hash (already identified in Exp 1 analysis)
- Inject per-run persona noise at the prompt level (±0.05 on OCEAN priors) rather than at selection

**3. If softmax is revisited, test tau=0.04-0.06 range:**
- Cold enough to preserve persona fidelity
- But even at tau=0.06, the diversity benefit is likely negligible given the structural ceiling
